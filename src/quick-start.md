# Quick Start

Get up and running with Lust in just a few minutes. This guide covers installing the CLI, writing your first script, and inspecting the generated bytecode.

---

## 1. Installation

### Option A: Via Cargo (Recommended)

If you have Rust and Cargo installed, install the Lust CLI and the language server directly:

```bash
cargo install lust-rs
cargo install lust-analyzer
```

Verify that the CLI is installed and available in your `PATH`:

```bash
lust --version
```

### Option B: Prebuilt Binaries

Precompiled releases are available for Linux x86_64:

```bash
curl -OL https://lust-lang.dev/downloads/lust-linux-x86_64.tar.gz
curl -OL https://lust-lang.dev/downloads/lust-linux-x86_64.tar.gz.sha256
shasum -a 256 -c lust-linux-x86_64.tar.gz.sha256
tar -xf lust-linux-x86_64.tar.gz
```

Add the extracted binary directory to your `PATH`:

```bash
export PATH="$PWD:$PATH"
```

## 2. Your First Script

Create a new file named `hello.lust`:

> 📂 **Запускаемый пример:** [`examples/basic/01_hello.lust`](https://github.com/lust-lang/lust/blob/perf/10x-jit-optimization-suite/examples/basic/01_hello.lust)  
> 💻 *Файл в репозитории компилятора:* `examples/basic/01_hello.lust`

```lust
-- hello.lust
println("Hello from Lust!")

local greeting: string = "Welcome to typed scripting"
local year: int = 2026

println(greeting .. " in " .. tostring(year) .. "!")
```

Run your program with the `lust` CLI:

```bash
lust hello.lust

# Or explicitly choose an execution backend:
lust hello.lust --jit=off                # Bytecode VM (JIT disabled)
lust run hello.lust --backend vm         # Bytecode VM
lust run hello.lust --backend cranelift  # Cranelift JIT (Dynasm retired)
lust run hello.lust --backend rust       # Rust AOT (#![no_std] lust-aot-rt)
lust run hello.lust --backend zig        # Zig AOT Native
```

**Output:**

```text
Hello from Lust!
Welcome to typed scripting in 2026!
```

You can also compile scripts ahead of time into native binaries, object files, or shared libraries:

```bash
# Rust AOT native binary (backed by #![no_std] lust-aot-rt)
lust build hello.lust --backend rust -o hello_bin

# Cranelift Object AOT (requires building lust with --features cranelift-aot)
lust build hello.lust --backend cranelift-aot -o hello_clif

# Zig AOT C-shared library
lust build hello.lust --backend zig --cdylib -o libhello.dylib
```

## 3. Project Configuration (`lust-config.toml`)

Lust projects can define an optional `lust-config.toml` in the working directory. This file enables optional standard library modules (such as file I/O and operating system access) and configures the execution environment:

```toml
[settings]
stdlib_modules = ["io", "os"]
jit = true
```

When `lust script.lust` is executed, the CLI automatically searches the current directory for `lust-config.toml` and applies your settings.

---

## 4. Inspecting Bytecode Disassembly

Lust compiles source code into high-density bytecode before execution. You can view the compiler's bytecode output using the `--disassemble` (or `-d`) flag:

```bash
lust --disassemble hello.lust
```

This dumps the constant pool, local variable tables, and opcode instructions, which is invaluable for debugging or understanding how hot loops are structured for the JIT.
